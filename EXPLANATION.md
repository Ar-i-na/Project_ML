# Объяснение репозитория

Этот файл — «карта» проекта: что делает каждый файл и почему выбрана
именно такая метрика. Прочитайте его перед тем, как трогать код.

## Почему macro-F1

Задание требует использовать **macro-F1** как основную метрику. Вот почему
это осмысленно, а не просто произвольное требование.

**F1-score** для одного класса — это среднее гармоническое precision
(«из того, что модель назвала классом X, сколько реально класс X») и
recall («из всех реальных X, сколько модель нашла»). F1 балансирует
между этими двумя ошибками: если модель либо слишком часто «кричит» X
(много false positives, низкий precision), либо слишком часто пропускает
X (много false negatives, низкий recall) — F1 просядет в обоих случаях.

**Macro-F1** — это F1, посчитанный отдельно для каждого класса, а затем
усреднённый **без учёта размера класса** (простое среднее арифметическое).
Это отличается от:
- **accuracy** — доли правильных ответов по всем документам сразу. Проблема:
  если один класс крупнее остальных, модель может получить высокую accuracy,
  просто хорошо предсказывая крупный класс и почти игнорируя маленькие.
- **micro-F1** (в multi-class без multi-label это то же самое, что accuracy) —
  тоже не показывает, если один класс работает сильно хуже других.
- **weighted-F1** — усредняет F1 по классам, но с весом = размер класса,
  то есть снова маскирует плохую работу на маленьком классе.

**Macro-F1 даёт каждому классу одинаковый голос**, независимо от того,
сколько в нём документов. Именно поэтому в задании просят смотреть на неё,
а не на accuracy: если ваша модель отлично угадывает `rec.sport.baseball`,
но плохо — `sci.space`, macro-F1 это честно покажет, даже если классы
примерно одного размера (у вас в проекте они специально сбалансированы,
но привычка использовать macro-F1 должна быть общей — это стандарт для
multi-class задач в принципе).

**Практический вывод:** при анализе всегда смотрите не только на итоговую
macro-F1, но и на F1 по каждому отдельному классу (это есть в выводе
`src.evaluate.print_metrics` и в `results/*_metrics.json`, поле
`per_class`) — так вы поймёте, какой конкретно класс «тянет» метрику вниз.

## Что делает каждый файл

### `config.py`
Единая точка настройки: список классов (`CATEGORIES`), `random_state` и
доля test-выборки. Все остальные файлы читают настройки отсюда — если
нужно поменять классы или seed, меняйте только здесь.

### `requirements.txt`
Единственный файл зависимостей: scikit-learn (TF-IDF, классификаторы,
метрики), pandas/matplotlib/seaborn (таблицы, графики). Этого достаточно
для EDA, baseline (`tfidf_logreg`, `tfidf_linearsvc`) **и** альтернативного
подхода (`tfidf_char_svm`) — никаких дополнительных библиотек с проблемной
сборкой (как gensim) в проекте больше нет.

### `src/data.py`
Отвечает за **загрузку данных**.
- `load_data(categories, subset, strip_meta, random_state)` — обёртка над
  `sklearn.datasets.fetch_20newsgroups`. Параметр `strip_meta` — это и есть
  переключатель для вашего исследовательского вопроса: при `True` вызывает
  `fetch_20newsgroups(..., remove=('headers','footers','quotes'))`.
- `dataset_overview(...)` — считает количество документов и статистику по
  длине текста для каждого класса. Используется на шаге 1 задания (EDA).

### `src/preprocess.py`
**Предобработка текста**, общая для всех подходов.
- `clean_text(text)` — убирает URL/email, цифры, знаки препинания, приводит
  к нижнему регистру.
- `clean_corpus(texts)` — применяет `clean_text` ко всему списку документов.
- `tokenize(text)` — простое разбиение по пробелам (пригодится, если решите
  добавить свои word-level эксперименты).

### `src/models.py`
**Сборка моделей.** Функция `build_pipeline(approach, **kwargs)` строит
готовый `sklearn.pipeline.Pipeline` (вектаризация + классификатор) по имени
подхода:
- `"tfidf_logreg"` — базовое решение задания (TF-IDF на словах + LogisticRegression).
- `"tfidf_linearsvc"` — тот же TF-IDF на словах, но с LinearSVC (для эксперимента
  «классификатор A vs B» при одинаковых признаках).
- `"tfidf_char_svm"` — **альтернативный подход**: TF-IDF на СИМВОЛЬНЫХ
  n-граммах (`analyzer="char_wb"`, по умолчанию 3–5 символов) + LinearSVC.
  В отличие от baseline, признаками становятся не целые слова, а кусочки
  слов — это ловит морфологию, суффиксы, устойчивые буквосочетания и
  устойчиво к редким словоформам/опечаткам. Работает целиком на
  scikit-learn, без внешних моделей и дополнительных библиотек.

Гиперпараметры (`ngram_range`, `C`, `min_df` и т.д.) передаются как
`kwargs`, чтобы `experiments/run_experiments.py` мог их менять, не трогая
этот файл.

### `src/evaluate.py`
**Метрики и confusion matrix.**
- `compute_metrics(y_true, y_pred, target_names)` — считает macro-F1
  (основная метрика), accuracy и precision/recall/F1 по каждому классу
  отдельно.
- `print_metrics(...)` — печатает это в читаемом виде в консоль.
- `plot_confusion_matrix(...)` — строит и сохраняет confusion matrix
  (нормализованную по строкам — то есть по долям, а не абсолютным числам,
  что важно, если классы не идеально сбалансированы).

### `src/error_analysis.py`
**Разбор ошибок** (шаг 7 задания).
- `get_misclassified(...)` — таблица всех неправильных предсказаний с
  текстом документа (первые 300 символов), истинным и предсказанным классом.
- `get_confused_pair(...)` — то же самое, но отфильтровано под конкретную
  пару классов (например, true=`sci.space`, predicted=`comp.graphics`) —
  удобно, чтобы разобрать именно ту путаницу, которая видна на confusion
  matrix, а не листать случайные ошибки.
- `top_confused_pairs(cm, target_names)` — по матрице ошибок находит,
  какие пары классов путаются чаще всего.
- `top_features_per_class(pipeline, target_names)` — для TF-IDF-моделей
  достаёт слова с наибольшим весом на каждый класс. Полезно, чтобы
  проверить гипотезу «модель выучила служебные слова из headers, а не
  тематическую лексику» — прямое отношение к вашему исследовательскому
  вопросу.

### `train.py`
**Главная точка входа.** Функция `run_experiment(approach, strip_meta,
model_kwargs, save_prefix)` прогоняет один эксперимент целиком: загрузка
данных → train/test split (один и тот же random_state для raw и stripped
версий, чтобы сравнение было честным) → предобработка → обучение →
метрики → confusion matrix → сохранение в `results/`. Также поддерживает
запуск из командной строки (`python train.py --approach ... --strip-meta`).

### `experiments/run_experiments.py`
**Запускает несколько экспериментов подряд** и собирает результаты в
сводную таблицу. Список `EXPERIMENTS` — это готовый стартовый набор из
5 конфигураций (баланс между «минимум 3» из задания и запасом на случай,
если что-то не сработает). У каждого эксперимента есть поле `why` —
объяснение, зачем он нужен и что с чем сравнивается; это прямо ложится
в формат отчёта, который просит ваш руководитель (что изменили / зачем /
результат / вывод). Результат — `results/experiments_summary.csv`
(таблица для сравнения) и `results/experiment_log.md` (текстовый лог,
куда останется дописать колонку «вывод»).

### `notebooks/01_eda.py`
Скрипт для первичного анализа данных (шаг 1 задания): распределение
классов, длина текстов, пример документа до/после удаления headers/
footers/quotes.

### `results/`
Пустая на старте — сюда всё сохраняется автоматически после запуска
`train.py` или `experiments/run_experiments.py`: JSON с метриками,
PNG confusion matrix, CSV со сводной таблицей, MD с логом экспериментов.
Это и есть тот «результат», который должен быть виден в репозитории
(пункт из задания про репозиторий).

## Как всё это связано с пунктами задания

| Пункт задания | Где реализовано |
|---|---|
| 1. Разобраться с данными | `src/data.py` (`dataset_overview`) + `notebooks/01_eda.py` |
| 2. Подготовить данные | `src/preprocess.py`, `strip_meta` в `src/data.py` |
| 3. Baseline TF-IDF + линейный классификатор | `src/models.py` (`"tfidf_logreg"`) |
| 4. Альтернативный подход | `src/models.py` (`"tfidf_char_svm"`) |
| 5. Минимум 3 эксперимента | `experiments/run_experiments.py` (список `EXPERIMENTS`) |
| 6. Сравнить результаты | `results/experiments_summary.csv` |
| 7. Анализ ошибок | `src/error_analysis.py` |
| 8. Выводы | `results/experiment_log.md` (дописываете сами) |
